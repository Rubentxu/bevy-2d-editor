### ⚠️ Spec correction: ActuatorBus movement (REQ-A-4)

The spec says "`ActuatorBus` moves to `editor-model/src/runtime/actuator_bus.rs`". Reality:
- The internal struct `ActuatorOutput` is already pure (uses `entity_bits: u64`, NOT Bevy `Entity` directly).
- The module-level `submit_actuator_output(entity: Entity, field: &str, value: PortValue)` function uses `bevy::prelude::Entity` for the **producer-side** API.
- `EditorSessionPort::runtime_actuator_outputs_mut() -> &mut ActuatorBus` itself is fine (bus is pure).

**Resolution for apply phase**:
- Move `ActuatorOutput`, `ActuatorBus` (struct + impl), `submit_actuator_output_pure(output: ActuatorOutput)` to `editor-model/src/runtime/actuator_bus.rs`.
- Keep `submit_actuator_output(entity: Entity, field, value)` wrapper in `editor-bevy/src/actuator_bus.rs` — it does `Entity::to_bits()` conversion then calls the editor-model API.
- The `apply_actuator_outputs` Bevy system (which converts `entity_bits` back to `Entity` and writes to components) stays in editor-bevy unchanged.

Add this WU split to Block A:
- **WU-A-3a**: move pure types to editor-model/src/runtime/actuator_bus.rs
- **WU-A-3b**: keep Bevy-conversion wrapper in editor-bevy/src/actuator_bus.rs

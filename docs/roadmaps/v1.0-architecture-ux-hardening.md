# v1.0 Architecture & UX Hardening — Execution Roadmap

## Program objective

Strengthen the existing product without losing capabilities, while converting target architecture and v1 promises into measurable gates.

## Working model

Each milestone contains:

- baseline evidence;
- one or more small PRs;
- automated tests;
- UAT;
- checkpoint;
- rollback/compatibility plan.

A milestone may change its implementation after the checkpoint while preserving its outcome.

---

## H5 — Slim editor-bevy

### Candidate extraction order

1. asset command/application semantics;
2. pure logic validation/authoring operations;
3. persistence-independent scene transformations;
4. non-Bevy registries/policies.

### Rule

Before moving a module, answer:

- does it require `bevy::World`, Bevy Resources, rendering or Bevy asset APIs?
- if not, is it domain logic or application orchestration?

Move only when tests can define the receiving boundary cleanly.

### Exit

`editor-bevy` dependency graph and module inventory clearly describe runtime/projection responsibilities.

## H10 — Product proof and release freeze

Use `examples/platformer-minimal` or its successor as canonical UAT project, but author it through actual supported UI actions rather than treating committed fixture files alone as proof.

### Required evidence

- fresh project creation;
- author actor/level;
- place instances;
- override instance;
- attach/edit logic;
- import at least one supported external resource if promised by v1;
- play and diagnose;
- apply/revert runtime tunable where supported;
- save/reload browser workflow;
- export/BSN supported workflow;
- recovery simulation;
- keyboard critical path;
- benchmark report;
- dependency exceptions report = no critical exceptions.

### Freeze rule

After H10 candidate passes, only release blockers, docs and evidence fixes enter the v1 branch.

# v1.0 Roadmap — Stabilization and Product Readiness

## Goal

Declare a stable product contract backed by architecture, data integrity, performance, accessibility and end-to-end authoring evidence.

## Relationship to hardening

This roadmap is the release gate. Structural work is executed through `v1.0-architecture-ux-hardening.md`.

A v1 candidate is not blocked on implementing every possible architectural improvement; it is blocked on critical exceptions and unmet product budgets.

## Product gates

### G1 Canonical game authoring

A user can create a small playable 2D project through supported editor workflows without hand-editing editor-owned JSON as a required step.

### G2 Data safety

- atomic/durable behavior documented per storage mode;
- failure injection tests;
- recovery workflow;
- format migration corpus;
- import/reimport interruption handling.

### G3 Architecture integrity

- crate dependency gate passes;
- model has no critical ambient service locators;
- production UI does not depend on raw mutable WASM globals;
- single normal mutation route;
- no critical architecture allowlist entries.

### G4 Performance

Versioned benchmark corpus includes:

- 10k entities;
- large tile level;
- multi-level world;
- large asset catalog;
- representative logic graphs;
- project search/retrieval;
- project open/hydration.

### G5 UX/accessibility

- coherent onboarding/sample project;
- consistent shortcuts/menu/palette;
- keyboard critical path;
- hierarchy tree semantics;
- clear active document/context;
- actionable validation;
- no known blocker-level UI placeholders.

### G6 BSN/project compatibility

- declared support matrix;
- deterministic outputs;
- round-trip corpus;
- migration tests;
- Bevy-version adapter assumptions documented.

### G7 Extension/import contracts

Stable vs experimental capability surfaces are clearly labeled. Stable APIs have compatibility/version policy.

### G8 Release engineering

- reproducible candidate build;
- all mandatory checks from same commit;
- release evidence bundle;
- rollback/hotfix procedure;
- changelog generated from verified state.

### G9 Diagnostics/recovery

Users receive actionable errors for initialization, validation, save, import and runtime problems. Silent no-op/fallback is not accepted for data-affecting failures.

## Definition of done

A user can create a multi-level 2D project, build reusable actors, wire gameplay, import art/data on supported paths, run and inspect the game, safely tune/apply changes, save/reopen/recover the project, export declared Bevy/BSN outputs and optionally use reviewed automation capabilities without compromising data integrity.

## Explicitly post-v1

Unless evidence shows they are required to close a gate:

- new Rig agent runtime/autonomous specialists;
- background agent maintenance;
- marketplace;
- CRDT collaboration;
- pixel-art editor;
- audio workstation tooling;
- mobile-first authoring;
- general 3D parity.

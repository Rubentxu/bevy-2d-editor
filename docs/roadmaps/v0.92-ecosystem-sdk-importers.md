# v0.92 Roadmap — Ecosystem, SDK and Import/Reimport

## Objective

Prove extensibility and external-tool interoperability.

## Sequence

| # | Item | Status | Notes |
|---|------|--------|-------|
| 1 | internal extension registry/capability permissions | ✅ DONE | `ExtensionManifest`, `Capability`, `Permission` types; `ExtensionRegistryPort` trait + `Arc<Mutex<dyn ExtensionRegistryPort>>` in `EditorSession` |
| 2 | recipe extension implementation | ✅ DONE | `builtin.logic-recipes` extension with `Capability::Recipes` |
| 3 | validator extension implementation | ✅ DONE | `builtin.scene-validator` extension with `Capability::Validators` |
| 4 | ExternalSource/provenance core | ✅ DONE | ADR-0041 accepted; `ExternalSource` provenance types in `editor-model` |
| 5 | Aseprite importer/reimporter | 🔲 Deferred to v0.93 | Requires SDK-061 importer protocol |
| 6 | LDtk importer/reimporter | 🔲 Deferred to v0.93 | Requires SDK-061 importer protocol |
| 7 | Tiled importer/reimporter | 🔲 Deferred to v0.93 | Requires SDK-061 importer protocol |
| 8 | extension compatibility/version documentation | 🔲 Deferred | Protocol not yet stabilised (ADR-0040 step 3) |

## Exit criteria

**Partially met:** At least three built-in capabilities use the same extension interfaces intended for future third-party use ( ✅ done: commands, recipes, validators). Reimport conflict handling is deferred to v0.93 alongside the importers.

## v0.93 follow-up (SDK-061)

Importers (Aseprite, LDtk, Tiled) and the stabilised importer protocol are the primary v0.93 deliverable. ADR-0041 provides the `ExternalSource`/`Provenance` foundation; the importer implementations build on that.

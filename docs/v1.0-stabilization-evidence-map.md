## 1. Scope and methodology

This document is the **first deliverable** of the v1.0-stabilization cycle. It answers:

1. What evidence already exists that the IDE works?
2. Which v1.0 product gates have coverage?
3. Which v1.0 gates have no coverage (gaps)?
4. What is the recommended next concrete work?

**Methodology:**

- **Test inventory:** count tests per layer (Playwright specs × cohort/tag, cargo `#[test]`/`tests/*.rs`, archcheck rules, docs-check rules).
- **Feature inventory:** read the command surface (`engine-bridge.ts` window bridges, `crates/editor-wasm/src/lib.rs` exports), the UI surface (`frontend/src/components/`), and the workflow surface (`examples/`, importers, recipes).
- **Coverage matrix:** map each v1.0 product gate (MASTER_ROADMAP) and each roadmap section (v1.0-stabilization) to the tests and features that exercise it.
- **Gap analysis:** explicit "no evidence" or "thin evidence" cells in the matrix.
- **Recommendations:** ordered by impact × cost, with the smallest acceptable v1.0 evidence packet identified.

**Out of scope:** agent runtime (Rig) work — paused per user directive 2026-09-06 until v1.0 gates pass.

## 6. Gap analysis — priorities

### 6.1 Highest-impact gaps (block v1.0 declaration)

1. **G1 — No canonical playable game.** Without this, "create a small complete 2D game" cannot be evidenced. **Recommended first concrete work.**
2. **G5 — No crash/interruption recovery story.** v1.0-stabilization explicitly lists this as a required gate. OPFS writes can be lost if the tab crashes between flush and OS write.
3. **G6 — No performance corpus.** The roadmap lists six specific benchmarks; none are wired.
4. **G8 — No compatibility policy.** Without it, downstream extensions and agents cannot be trusted to upgrade.
5. **G2/G4 — No declared v1 format list and Git workflow.** ADR-0045 exists but the format versioning is not committed.

### 6.2 Medium-impact gaps

6. Data-safety: format/migration support matrix (small corpus, no declared matrix).
7. UX: no end-to-end tutorial project.
8. UX: comprehensive tab-order + focus-trap audit.
9. Release engineering: signed/versioned artifacts + rollback procedure.

### 6.3 Pre-existing carry-forward (NOT introduced by this cycle)

- **C-3:** `cargo test --workspace --release --locked` exceeds 10 min on local runner; affects CI cycle time. This is a release-engineering concern; also blocks the "no regression" guarantee during the stabilization cycle.
- **M-2, M-3, M-5:** low-priority docs/archcheck warnings, not blockers.
- **rule-7 docs-check warnings:** 23 specs + 11 roadmaps without status markers; affects documentation hygiene.

### 6.4 Smoke cohort 60 s budget breach (pre-existing)

`playwright.smoke.config.ts` declares the cohort MUST stay under 60 s, but `engine.spec.ts` alone runs in ~1.2 m. Pre-existing condition; recovery-3 did not regress it. Resolution path: either trim `engine.spec.ts` from smoke cohort (move to `@full`) or split its cases into smaller specs.

## 7. Recommended next concrete work

Ordered by **impact × cost** with the smallest acceptable v1.0 evidence packet identified first.

### P1 — Canonical playable sample game (closes G1)

- **Scope:** Build a 2D platformer minimal (player + ground + 1 enemy + 1 pickup + death logic) **entirely inside the editor**, export to `.bsn`, import in a Bevy 2D harness, run, assert gameplay state.
- **Artifact:** `examples/platformer-minimal/` (new directory): `project.json`, scene asset(s), schema(s), logic graph(s), `bundled.bsn`, `run-bevy-harness.sh`, README.
- **Evidence:** new `playwright.e2e-game-creation.config.ts` cohort with one test "create the canonical sample via UI, export, roundtrip".
- **Cost:** ~1–2 days (depends on whether `examples/` already has a Bevy harness).
- **Closes:** G1 (large).

### P2 — Crash/interruption recovery corpus (closes G5)

- **Scope:** Playwright tests that:
  1. Open editor, modify state, kill page mid-save, reload, assert no data corruption.
  2. Open editor, modify state, force WASM panic during flush, assert recovery state.
  3. Force OPFS quota exceeded, assert user-facing error.
- **Artifact:** `frontend/tests/crash-recovery.spec.ts`, scripted via Playwright's `page.context().setOffline()` and `jest-mock` for WASM panic.
- **Cost:** ~1–2 days.
- **Closes:** G5.

### P3 — Performance corpus (closes G6)

- **Scope:** Add six Playwright performance specs:
  1. 10k entities roundtrip (`engine.spec.ts:526` scaled up).
  2. Large tile level paint/erase.
  3. Multi-level world navigation latency.
  4. 500-asset catalog listing.
  5. 200-node logic graph dispatch.
  6. 1000-file project search.
- **Artifact:** `frontend/playwright.performance.config.ts` + 6 specs with budget assertions (e.g. "open 10k entities < 5 s").
- **Cost:** ~3 days (requires benchmark harness).
- **Closes:** G6.

### P4 — Compatibility policy (closes G8)

- **Scope:** Add `docs/compatibility-policy.md` declaring v1 format versions (project.json, scene asset, logic graph, schema), extension API, and capability tool surface. Pin a 12-month deprecation window.
- **Cost:** ~0.5 day.
- **Closes:** G8.

### P5 — Declared v1 format list (closes G4 partial)

- **Scope:** Add `docs/v1-format-manifest.md` enumerating: schema registry version, scene asset schema version, logic graph version, project format version. Cross-link to `migration.rs` migration paths.
- **Cost:** ~0.5 day.
- **Closes:** G4 partially.

### P6 — Git workflow documentation (closes G2 partial)

- **Scope:** Add `CONTRIBUTING.md` documenting filesystem-mode plan (when implemented), Git roundtrip steps, conflict resolution.
- **Cost:** ~1 day (mostly writing).
- **Closes:** G2 partially.

### P7 — Tutorial sample (UX onboarding) (closes UX §5.3 partial)

- **Scope:** A guided tutorial that opens automatically when no project is detected. Walks user through: create entity → add component → create scene asset → save → reload → play mode.
- **Cost:** ~3 days.
- **Closes:** UX onboarding gap.

### P8 — Trim smoke cohort (housekeeping)

- **Scope:** Move `engine.spec.ts` out of `playwright.smoke.config.ts`. Keep only `smoke.spec.ts`, `app-characterization.spec.ts`, `capabilities-smoke.spec.ts`, `editor-ready.spec.ts` in smoke. Add `engine.spec.ts` to `playwright.full.config.ts` only.
- **Cost:** ~0.5 day.
- **Closes:** pre-existing 60 s budget breach.
